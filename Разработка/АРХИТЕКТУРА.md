# Архитектура Airfoil Studio

Карта кода и данных: где что лежит, как течёт расчёт, за что цепляться при правках.
Номера строк — **на момент сборки этого архива** (файл `программа\index.html`,
644 КБ); после правок номера сдвинутся, ищите по названиям функций и по
заголовкам-комментариям вида `/* ================= … ================= */`.

---

## 2. Глобальное состояние

| Имя | Что это |
|---|---|
| `S` | `{ profiles: [], sel, edit, editName, undo: [] }` — база профилей, выбранный, буфер редактора, стек отмены |
| `CFG` | все настройки реза/станка/лонжерона (см. `DEF_CFG`) |
| `LAST` | результат последнего расчёта (`computeCut`), из него рисуются симуляция, G-код, размеры |
| `VIEW` | 3D-превью: `yaw, pitch, zoom, px, py` |
| `VIEW2` | 2D-торцы: независимые `zoom/px/py` для `L` и `R` |
| `SIM` | проигрыватель симуляции: точки, длины, время, скорость |
| `ED` | состояние редактора: зум, сдвиг, предпросмотр задней кромки |
| `PFZ` | зум превью профиля на вкладке «Профили» |
| `LUTC` | кэш «профиль → нормализованные половины» для быстрой отрисовки |
| `FH_BASE` | ссылка на выбранный файл-базу (File System Access API) |

Служебные ключи хранилища:

* `localStorage["airfoilStudio.profiles.v2"]` — свои профили (библиотечные не пишутся);
* `localStorage["airfoilStudio.cfg.v2"]` — настройки;
* `localStorage["airfoilStudio.layout.v1"]` — ширина колонок и высоты панелей;
* `localStorage["airfoilStudio.defsFix.v3"]` — одноразовый флаг правки дефолтов;
* IndexedDB `airfoilStudio` → store `kv` → ключ `baseHandle` — файл-база.

## 3. Форматы данных

### Профиль

```js
{
  name: "NACA 2412",       // имя, по нему ищутся корень/конец и склеивается файл-база
  pts: [[x, y], …],        // контур, НОРМИРОВАН на хорду: x ∈ [0,1], y в тех же долях
  src: "uiuc" | "naca" | "edit" | …,  // "uiuc" = библиотечный, в файл-базу не попадает
  chord: 250               // хорда в мм, задаётся в редакторе; может отсутствовать
}
```

`pts` — замкнутый обход: передняя кромка → верх → задняя кромка → низ (без
повторения первой точки). Передняя кромка в `x = 0`, задняя — в `x = 1`, `y` вверх.
Всё, что приходит из `.dat`, DXF, STEP, проходит через `canonicalize()`:
поворот к ПК, нормировка, разворот в правильную сторону.

### Настройки (`DEF_CFG`, строки ~888…906)

```js
root: { idx, chord, x, y, rot }      // корневая нервюра: профиль и положение на торце
tip:  { idx, chord, x, y, rot }      // концевая
span, wireD, kerf, step, feed,       // размах (башни), диаметр проволоки, доп. зазор,
lead, faceOff,                       // шаг по контуру, подача, отъезд, отступ от торца
bw, bh, bl, bzOff,                   // заготовка: ширина, высота, длина, сдвиг по Z
tipOwn,                              // концевая хорда своя (а не масштаб корневой)
spar: { on, kind, side, d, w, h, w2, h2, snap, root{x,y}, tip{x,y}, root2, tip2 }
ax:   { Lx:"X", Ly:"Y", Rx:"A", Ry:"B" },   // какие буквы осей у башен
inv:  { Lx, Ly, Rx, Ry },                   // инверсия осей
zero: { Lx, Ly, Rx, Ry },                   // машинные нули
teMirror, teSide,                           // флаги миграций (вид с ЗК)
rapid:300, dwell:2, on:"M3", off:"M5",      // холостые, пауза, команды проволоки
dec:3, nStep:10, lineN:false, head:"", foot:""
```

`inv.Lx` и `inv.Rx` по требованию заказчика **всегда включены**; `rapid = 300`;
в «Пенорезке» отъезд назад 0, подача 150.

### Результат расчёта (`LAST`)

```js
{
  R, T,                // контуры корня и конца в координатах заготовки, мм
  ops: [ { rapid, L:[x,y], R:[x,y], note, open, pts } … ],  // проходы обеих башен
  N, len, feed, tmin,  // число точек, длина пути, подача, время
  block: { x0,x1,y0,y1,z0,z1 },   // заготовка
  M: { bl, span, bz, free, fits, kL, kR },  // геометрия «башни шире заготовки»
  tw,                  // пары координат башен
  spar: [ { side, label, open, sR, sT } ],  // вырезы лонжеронов
  bbox
}
```

### Проект «Пенорезки» (`проект_….json`)

Кнопки `#cPrjSave` / `#cPrjOpen` (+ скрытый `#cPrjFile`), функции `projData()`,
`projOpen()`, `projEndSnap()`, `projSparSnap()`, `projFileName()`, `projSave()`.

```js
{
  kind: "airfoil-studio-project", v: 1, saved: "2026-11-16 10:12",
  cut: {
    root: { name, chord, x, y, rot, pts: [[x,y]…], profChord },  // pts — на всякий случай
    tip:  { … },
    span, wireD, kerf, step, feed, lead, faceOff, bl, bw, bh, bzOff, teOff,
    spar: { on, kind, side, d, w, h, w2, h2, root:{x,y}, tip:{x,y}, root2, tip2 }
  }
}
```

* **Настройки станка** (`ax`, `inv`, `zero`, `rapid`, `on`/`off`, `head`/`foot`) в проект
  не входят: они про машину, а не про деталь.
* Профиль при открытии ищется **по имени**; нет в базе — добавляется с `src:"edit"`.
* Хорда проекта **главная**: пишется в `CFG.root/tip.chord`, а при расхождении и в
  `p.chord` записи профиля (иначе `syncChords()` вернул бы старую и рез был бы другим).
* Порядок восстановления: профили → хорды → `CFG.spar = migrateSpar(...)`
  (привязка «2 прямоугольников» к обводу считается по хорде) → `syncFormFromCfg()` →
  `refreshCut()` → очистка поля УП.
* Старое «Выгрузить проект» в «Станке» (`#prjSave`/`#prjLoad`) — это другой формат
  (`{v:2, profiles, cfg}`, полный дамп): не путать.

## 4. Как течёт расчёт

```
CFG + профили
   │
   ├─ buildEnd(cfg, prof, N)      контур нервюры в мм, с учётом kerf
   │     • splitHalves/prepHalf/yAtX — гладкие половины по косинусной выборке
   │     • mapPt(cfg,x,y)          нормированный профиль → мм на торце
   │     • offsetPoly(kerf/2)      зазор проволоки
   │
   ├─ sparDefsResolved()          полости лонжерона (труба / прямоугольник / 2 шт.)
   │     • sparSnapPoint()        привязка к обводу
   │     • buildCavity()          контур полости на торце (+ cx, cy, r — осевая круга)
   │     • wallHitContour()       пересечение луча со обводом: точка + i + u (ok)
   │     • ptAt(pts, fi)          точка обвода по ДРОБНОМУ индексу станции
   │
   ├─ towerMap()                  башни могут стоять шире заготовки: kL, kR
   ├─ toTowers(r, t, M)           координаты нервюр → координаты башен
   └─ ops[]                       единый непрерывный проход: вход с торца,
                                  контур, вход в паз, обвод, выход, возврат
```

**Заход в закрытую полость — всегда по её осевой.** Для `tube`/`box` точка входа —
это пересечение вертикального луча из центра полости с нужной половиной обвода
(`wallHitContour` → `i + u`), поэтому заход и выход идут по одной вертикали и
строго под 90° к окружности. Станция обвода (`st(ucR)`) осталась только как
запасной вариант: полость торчит за обвод или вертикаль не находит стенку.
`walkTo` работает с дробными индексами, так что башня останавливается ровно
под вертикалью, а не на ближайшей станции.

Дальше из `LAST`:

* `renderCut()` — 3D-сцена (две башни, проволока, заготовка);
* `renderCut2D()` — вид торцов с независимым зумом и «вырезами лонжерона»;
* `simFromGeom()` / `simFromGcode()` — симуляция (второй режим читает готовую УП);
* `buildGcode()` — УП для Mach3.

`toTowers` / `fromTowers` — обратимая пара: вторая нужна, когда путь читается
из готовой УП (`parseGcode`) и надо перевести ходы башен обратно в точки нервюр.

## 5. G-код

`buildGcode()` (строка ~3729):

* шапка: комментарии с корнем/концом, размахом, проволокой, kerf, подачей, заготовкой;
* `G21` (мм), `G90` (абсолютные), `G94` (подача в мм/мин), затем `CFG.head`;
* `move()` собирает строку из 4 осей: `X Y A B` (буквы берутся из `CFG.ax`,
  порядок всегда X, Y, A, B), значения: `zero + (±coord)` по `CFG.inv`, decimals `CFG.dec`;
* `G0` — холостые, `G1` — рез, подача ставится в первой режущей строке;
* включение проволоки `CFG.on` (M3) + пауза `G4 P` (dwell), выключение `CFG.off` (M5);
* `CFG.foot`, `M30`;
* `CFG.lineN` — нумерация строк с шагом `CFG.nStep`.

Обратный разбор готовой УП — `parseGcode()`: вытаскивает движения, через
`fromTowers()` возвращает точки нервюр и подставляет в симуляцию.

## 6. Экспорт / импорт

| Что | Функция | Особенности |
|---|---|---|
| `.dat` | `datText()` | координаты в мм по хорде, шапка с именем и хордой |
| DXF R2000 | `dxfText()` | `$INSUNITS 4`, `$MEASUREMENT 1`, замкнутый контур, реальные мм |
| STEP AP214 | `stepText()` | контур в мм для SolidWorks/FreeCAD |
| PDF шаблон нервюр | `ribPdf()` ← `ribSheetCanvas()` + `ribA4Pages()` | масштаб 1:1, лист A4, контуры сплошные, сгибы пунктиром (`dashPath`) |
| «Выгрузить проект» | `saveTypes()` + `saveBlob()` | пакет файлов (профили, настройки, УП) в zip/папку |
| Проект «Пенорезки» | `projData()` → `projSave()` → `saveBlob()` | JSON `kind:"airfoil-studio-project"`: профили с координатами, хорды, лонжерон, рез; станок не входит |
| Импорт | `importFiles()` | `.dat`, DXF, STEP — по расширению, дальше `canonicalize()` |
| Разбор DXF | `parseDxf()` | LWPOLYLINE и POLYLINE/VERTEX |
| Разбор STEP | `parseStep()` | POLYLINE, иначе все CARTESIAN_POINT |

Хорда для экспорта — `exportChord()`: `p.chord` выбранного профиля, иначе
дефолт `CFG.root.chord`. Масштаб всегда реальный, ничего не «подгоняется».

## 7. Управление интерфейсом

* Переключение вкладок — `switchTab(name)`, кнопки `nav#tabs button[data-tab]`.
* Формы: `syncFormFromCfg()` **заполняет поля из CFG**, `readCutForm()` и
  `readMachineForm()` **читают поля обратно в CFG**, `refreshCut(rebuild)` —
  пересчитывает и перерисовывает. Любое изменение настройки заканчивается
  `refreshCut()` + `saveCfg()`.
* `syncChords()` — связывает хорду из записи профиля с полями расчёта.
* `updateSparFields()` + `renderSparPreview()` + `#sparYInfo` — лонжерон:
  поля, предпросмотр на обеих нервюрах и расшифровка «откуда Y».
* Раздвижные панели — `initSplitters()`, `layoutCols()`, `saveLayout()`.

### Рецепт: добавить новую настройку

1. Дефолт — в `DEF_CFG` (иначе `loadCfg()` её не поднимет).
2. Поле — в HTML нужной вкладки, `id` по образцу соседних.
3. Чтение/запись — в `syncFormFromCfg()` и `readCutForm()`/`readMachineForm()`.
4. Пересчёт — вызвать `refreshCut()` там, где меняется значение.
5. Старые сохранённые настройки — при необходимости миграция
   (`migrateSpar`, `migrateMirror`, `migrateSide`, `migrateTipOwn`) + `saveCfg()`.

### Рецепт: новая операция редактора

`op…()` меняет `S.edit` (через `snapshot()` для отмены), затем `renderEditor()`
и `buildTable()`. Сохранение — только через нижнюю полосу (`.savebar`).

## 8. Старт программы (`init()`, ~5143)

1. `initSplitters()`, `loadCfg()` (+ миграции, `forceFixedDefaults()`).
2. `loadProfiles()` из localStorage; если пусто — `seedProfiles()` (NACA + базовые).
3. Пересборка встроенных NACA и выравнивание «покосившихся» профилей (`alignSafe`).
4. `mergeUiuc()` — доливка библиотечных профилей, которых нет по имени/ключу.
5. `mergeFileBase()` — **доливка профилей из `airfoil-base.js`** (тост, если что-то добавилось).
6. `resolveCfgProfiles()` — корень/конец ищутся по имени, а не по номеру.
7. Навешивание обработчиков на все элементы (вкладки, кнопки, ползунки, зум).
8. Первый `refreshCut()`.

Для XP-версии дополнительно: загрузчик файл-базы асинхронный, поэтому после
загрузки вызывается `window.fileBaseLateLoad()` — он ещё раз сливает базу и
обновляет экран (см. `БАЗА_ПРОФИЛЕЙ.md`).

## 9. Ловушки, о которых стоит помнить

* **`pts` всегда нормированы на хорду.** Если рисуете/считаете в мм — умножайте
  на хорду (`exportPoints()`), иначе профиль «схлопнется» в 0…1 мм.
* **Индексы корня/конца — только через `resolveCfgProfiles()`.** Прямое
  `CFG.root.idx = i` после удаления профиля даёт рез «не тем» профилем.
* **Индекс станции обвода может быть дробным.** `iInR/iOutR` — это `i + u`
  (см. `ptAt`), поэтому по контуру ходим только через `ptAt(pts, fi)`;
  `pts[Math.round(fi)]` вернёт наклон и «прыжок» на полшага.
* **Шрифты в canvas** на XP — только Arial/Tahoma (Segoe UI там нет).
* **`gap` во flex** не работает в Firefox 52 — в XP-сборке это лечит полифилл,
  но новую вёрстку лучше делать на margin/padding, а не на `gap`.
* **Не использовать `Blob.text()`** — в XP-сборке заменяется на `_blobText`,
  но проще сразу писать `await _blobText(f)`-совместимый код (или FileReader).
* **Файл-база пишется целиком** — не держите в `airfoil-base.js` ничего, кроме
  `window.AFOIL_FILE_BASE = [...]`.
* **Ничего не удаляем из базы при слиянии** — это правило заказчика: только добавлять.
