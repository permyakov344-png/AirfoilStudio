# История проекта в исходном виде

Здесь лежит «сырая» история работы над программой — то, из чего собраны
`ИСТОРИЯ.md` и `АРХИТЕКТУРА.md` в корне папки. Полезна, когда нужно вспомнить
**почему** сделано именно так, или найти точную формулировку требования.

## Что внутри

| Файл | Что это |
|---|---|
| `ЖУРНАЛ-ИЗМЕНЕНИЙ.md` | **журнал правок, ведётся автоматически**: дата, файл, размер, сколько строк изменилось, номер снимка |
| `СОСТОЯНИЕ.txt` | короткая сводка: когда архив обновлялся, размеры и SHA256 `index.html` и XP-версии, сколько снимков, где zip |
| `журнал-слежения.log` | технический лог «часового» (`watch-history.ps1`): что и когда он сделал, ошибки сборки |
| `снимки\` | копии файла программы на каждое изменение + исходный снимок на 11.11.2026 (хранятся последние 40) |
| `Переписка-по-проекту.md` | все запросы и ответы по проекту, по датам (22.10.2026 →), без служебных вызовов инструментов |
| `Авто-сводки-состояния.md` | технические срезы проекта: среда сама сжимала длинный разговор в сводку «что сделано / что решено / где остановились» — 31 срез по датам |

## Как этим пользоваться

* **Найти требование заказчика** — открыть `Переписка-по-проекту.md` и искать
  по ключевому слову (Ctrl+F): «лонжерон», «хорда», «отъезд», «dxf», «xp».
* **Увидеть, когда и что менялось** — `ЖУРНАЛ-ИЗМЕНЕНИЙ.md`: он ведётся сам,
  каждая запись ссылается на снимок файла программы.
* **Откатиться к прежнему состоянию** — взять нужный файл из `снимки\`
  (имя = дата и время) и положить вместо `index.html`. Затем пересобрать XP:
  `инструменты\пересобрать-XP.bat`.
* **Понять, почему код такой** — `Авто-сводки-состояния.md`: там решения
  зафиксированы коротко и по делу, без пересказа.
* **Сравнить версии** — `снимки\` против текущего `программа\index.html`.

## Что важно знать

* Служебные команды, вывод инструментов и рассуждения модели из переписки
  **удалены** — оставлены только реплики по существу. Поэтому переписка
  читается легко, но не является дословным логом сессии.
* В переписке встречаются упоминания путей того компьютера, где шла разработка
  (`C:\Users\user\...`) — при переносе они не актуальны, ориентируйтесь на
  структуру папки `Разработка`.
* Переписка — рабочая, не отредактированная под публикацию: там есть и ошибки,
  и отменённые решения. Это нормально, это история.
